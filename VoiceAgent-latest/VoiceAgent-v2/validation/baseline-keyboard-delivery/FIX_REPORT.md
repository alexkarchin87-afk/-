## Поле ввода: что изменено

**CONFIRMED по коду:** в MainActivity не был задан режим реакции на клавиатуру; imePadding находился на самом Composer, а не общем контейнере. Для плавающего окна не было проверки позиции и высоты относительно видимой области экрана. Панель привязывалась к правому краю по ширине пузыря, даже когда открыта широкая карточка чата. **LIKELY:** сочетание системного перемещения/изменения размеров и собственного layout объясняет описанный скачок; точная последовательность на устройстве без UI-теста неизвестна.

- `app/src/main/AndroidManifest.xml` → MainActivity → задан adjustResize, чтобы окно изменяло доступную область, а система не выбирала режим панорамирования эвристически. Значение проверено также в merged manifest после Gradle.
- `ui/MainScreen.kt` → MainScreen/PhoneLayout → один imePadding на общем контейнере чата, убран с Composer. Список сообщений отдаёт место клавиатуре, поле не получает отступ размером с клавиатуру внутри своего измеряемого блока. Navigation bar padding оставлен с обычным механизмом потребления Compose insets. Та же общая обработка покрывает desktop/windows layouts.
- `overlay/OverlayBubbleController.kt` → BubbleContent/show → adjustResize для окна, чтение getWindowVisibleDisplayFrame после layout, ограничение координат и максимальной высоты. Keyboard height повторно не вычитается из уже уменьшенной видимой области. Предпочтительное положение пользователя хранится отдельно от временной коррекции при появлении IME. При изменении доступной области положение рассчитывается заново; listener удаляется при dispose.
- `overlay/OverlayPosition.kt` → fitOverlayPosition → чистый расчёт допустимых координат по фактическим размерам окна, включая защиту от временно слишком большого окна во время перемеривания.
- `ui/WindowsCornerPopup.kt` и WindowsLayout → список/приветствие получают оставшееся место через weight(fill=false), оставляя место Composer и кнопкам; приветствие прокручивается при нехватке высоты. Функциональность списка, отправки, быстрых команд сохранена.

Проверки: компиляция, merged manifest, 6 JVM-тестов геометрии. Эти тесты не воспроизводят анимацию IME, Android WindowManager или реальные размеры Compose и не доказывают отсутствие визуальных скачков на OnePlus.

## Дополнительные небольшие исправления

**CONFIRMED:** `OverlayBubbleController.BubbleContent` передавал FloatingSparkButton пустой onClick; detectDragGestures не вызывает onDragEnd для обычного неподвижного тапа. Тап теперь открывает/закрывает панель через clickable, drag detector отвечает только за перетаскивание. Не создаётся дополнительный обработчик, который выполняет тот же тап повторно.

**CONFIRMED:** `scheduleAutoHide` повторно запускался при входящем Heard/Reply даже при открытой панели; режим «показывать всегда» также не учитывался таймером. Теперь открытая панель и настройка alwaysVisible блокируют автоскрытие как при планировании, так и перед hide. VoiceAgentService передаёт актуальное значение существующей настройки; выключение оверлея/сервиса по-прежнему закрывает его явно.

**CONFIRMED:** Composer хранил черновик через remember, поэтому он терялся при пересоздании той же композиции Activity. Использован rememberSaveable. Это не долговременное хранилище черновиков: закрытие и новое создание плавающего окна/переход между разными layouts не гарантируют его сохранение.

Эти небольшие UI-правки проверены кодом, компиляцией и Lint; автоматического теста физических жестов, автоскрытия на устройстве и восстановления Compose state не выполнялось. Сценарий — KEYBOARD_TEST.md.
