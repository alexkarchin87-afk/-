# Ручная проверка текущих исправлений

Эти проверки не выполнялись в облачной среде. Сначала установите полную Vosk-модель и соберите новый APK по DEVICE_DIAGNOSTICS.md. Не используйте предыдущий APK для проверки новых правок.

1. Откройте приложение, включите агента, дождитесь загрузки модели. Проверьте обычный текстовый ответ.
2. «Ваня, открой Telegram» → подтвердите «да» из того же голосового канала. Убедитесь в фактическом открытии; повторите. Маршрут подтверждения сохранён.
3. Запустите описание экрана; после подтверждения, пока ожидается LLM, выключите агента через UI. Поздний ответ не должен озвучиться/появиться после перезапуска.
4. Повторите остановку во время генерации тестового конспекта или отдельного проекта. После остановки не должно появиться позднее сохранение. Успешно завершённый до остановки файл должен остаться.
5. Для проверки успешного пути создайте короткий тестовый конспект без остановки: проверьте сохранение и озвученное подтверждение.
6. Создайте несекретное тестовое уведомление. Запросите «что нового», подтвердите действие, отключив сеть до LLM-запроса. После ошибки восстановите сеть и повторите: непрочитанное из-за ошибки уведомление должно снова попасть в пересказ, если ещё находится в буфере. Не перезапускайте процесс между попытками: NotificationBuffer не персистентен.
7. Во время успешного пересказа создайте второе уведомление; следующий запрос должен пересказать его. Учитывайте указанные в FIX_REPORT.md ограничения размера/временных меток.

Фильтр диагностических логов:

```sh
adb logcat -v threadtime -T 1 'VA_STT:I' 'VA_UI:I' 'VA_ROUTE:I' 'VA_TELEGRAM:D' '*:S' > voiceagent-safe.log
```

Фильтр не содержит текстов уведомлений/LLM, поэтому результат проверки их содержания фиксируйте наблюдением на устройстве, без передачи личных данных. Не отправляйте полный logcat, токены или базу уведомлений. Эта инструкция не предполагает наличие отдельной работающей голосовой команды Interrupt/Reset; для отмены используется остановка сервиса через существующий UI.
