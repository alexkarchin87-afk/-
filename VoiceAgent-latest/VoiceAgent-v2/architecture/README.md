# Навигация и правила архитектуры

Начните с [карты](../ARCHITECTURE_MAP.md): функция → владелец → Gradle-модуль → класс/функция → путь → зависимости → тесты. Все крупные подсистемы имеют README. Реальных Gradle-модулей два; владельцы в реестре являются архитектурными областями, а не новыми модулями.

`components.json` — проверяемый реестр семантики. Описания и принадлежность задаёт разработчик, генератор не выводит назначение класса из его имени. Каждый production Kotlin-файл имеет ровно одного владельца. Все Kotlin-тесты должны быть зарегистрированы; один интеграционный тест может проверять несколько владельцев.

После добавления/перемещения исходника:

1. Измените явные `files`, `tests`, `purpose`, `readme` соответствующей области в `components.json`.
2. Обновите README владельца. Новое направление зависимости требует осознанного изменения `allowed_dependencies`, а не автоматического принятия текущих импортов.
3. Выполните `python3 tools/generate_architecture_map.py`, затем `python3 tools/generate_architecture_map.py --check` и `python3 -m unittest discover -s tools/tests -v` из корня Android-проекта.
4. Запустите профильные Kotlin-тесты и сборочные проверки из BUILD_GUIDE_RU.md.

CI `.github/workflows/voiceagent-architecture.yml` в корне репозитория выполняет шаг 3 без Android SDK/модели/API-ключей. Он не заменяет Kotlin/Lint/device проверки.

Генератор анализирует literal `include(":...")` и `project(":...")` в Gradle Kotlin DSL, Kotlin imports (включая wildcard), top-level объявления, ссылки в том же package и полные имена. Проверяет циклы Gradle, объявления AndroidManifest, отсутствующие исходники/тесты/README, локальные Markdown-ссылки в README владельцев, дубликаты владельцев и запрещённые направления. `--check` сравнивает карту целиком, поэтому изменение путей/классов/импортов без регенерации приводит к ошибке.

Ограничения: это лексический анализ, не компилятор Kotlin. Dynamic Gradle configuration, reflection, string class names, DI runtime graph и интерполяция в строках не моделируются. Wildcard imports консервативны; nested members индексируются через владельца top-level типа. Одноимённые идентификаторы могут давать лишние same-package связи. Реестр тестов показывает расположение проверок, а не фактическое покрытие каждого класса. Проверки компиляции остаются обязательными.

Исходный разделённый package `com.voiceagent.oneplus13.core` сохранён между двумя Gradle-модулями ради совместимости. Путь и модуль в карте различают их; обратная ссылка из ai-engines на app запрещена. Новые Gradle-модули в этом проходе не вводились: сначала нужны стабильные контракты для существующей связанной группы внутри app.
