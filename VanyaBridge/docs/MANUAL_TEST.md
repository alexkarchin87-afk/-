# Приёмка на Windows 11 и OnePlus 13

Эти проверки **не отмечены выполненными** в среде Linux. Записывайте реальный результат каждого шага.

## Подготовка

1. Запустить `START_WINDOWS.bat --host СВОЙ_LAN_IP`. Убедиться, что окно работает, адрес/сертификат показаны, процесс не перезапускается.
2. В TestFolder создать `test.txt` и поместить безопасный `mountains.jpg`. Установить VS Code в стандартную папку.
3. В «Разрешениях» включить open_url, launch, wallpaper и при необходимости open_file. Read-only команды включены изначально.
4. Установить `releases/VanyaBridge-debug.apk` на OnePlus 13. Сопрячь по README, подтвердить на обоих устройствах.
5. Проверить ввод текста при открытой клавиатуре: поле остаётся у клавиатуры, история сжимается/прокручивается. Повернуть экран: черновик и подключение должны сохраниться, запрос не отправляется повторно.

## Пять сценариев — повторить на desktop и Android

| Шаг | Ожидаемый результат |
|---|---|
| «Открой YouTube на компьютере» | WAITING_APPROVAL, окно ещё не открывается. После «Разрешить» — REQUESTED, фактически проверить открытие youtube.com на ПК. |
| «Покажи файлы в моей тестовой папке» | COMPLETED, виден test.txt. Содержимое посторонних каталогов не выводится. |
| «Открой VS Code» | Подтверждение, затем REQUESTED и реальное окно VS Code. Если программа не установлена — FAILED с объяснением. |
| «Найди изображения гор для обоев» | Реальные результаты Wikimedia либо честное сообщение о недоступности/нуле результатов. Открыть выбранное изображение для проверки источника. |
| Выбранный результат → обои | Новая задача WAITING_APPROVAL. Сначала отклонить — обои не меняются. Повторить, подтвердить — Windows подтверждает вызов и обои реально меняются. |

Дополнительно проверить локальный вариант `Установи обои mountains.jpg`: он не зависит от поиска Wikimedia.
Повторное самостоятельное отправление новой команды — новая задача. Повторная доставка уже принятого UUID не должна повторять действие.

## Сбои и безопасность

1. Пока задача ждёт разрешения, нажать «Отменить». Подтверждение отменённой задачи не выполняет действие.
2. Отключить интернет: локальное соединение Wi-Fi и просмотр файлов должны работать; поиск/чтение внешних страниц завершаются ошибкой/тайм-аутом.
3. Отключить Wi-Fi телефона на 10 секунд, затем включить. Статус должен восстановиться без автоматического повторения задач.
4. Остановить desktop во время ожидания разрешения и снова запустить. История сохраняется, задача CANCELLED, изменения не выполняются автоматически. Разрешения действий после рестарта снова выключены.
5. Отозвать телефон в «Устройствах»: новые запросы отклоняются. Для восстановления нужен новый код и согласие.
6. При сопряжении изменить один символ SHA-256: соединение должно быть отклонено. Неверный код после пяти попыток требует выпуска нового кода.
7. `Открой файл ../secret.txt`, абсолютный Windows-путь, ссылка/junction на другую папку, CMD/EXE файл — отказ, даже после подтверждения.
8. Установить отсутствующий/повреждённый файл обоев — FAILED без ложного «обои установлены».
9. «Напиши стихотворение» в Ultra Free — честное объяснение неподдерживаемой команды. Standard — сообщение, что провайдер не подключён. Никаких платных запросов.
10. Playwright без установленного Chromium — FAILED. После установки проверить разрешённую страницу Wikipedia; содержимое страницы не должно запускать инструменты.

## Диагностика без секретов

На ПК вкладка «Журнал» содержит UUID/состояния без текстов запросов. Перепишите UUID проблемной задачи, состояние, время и шаг сценария.
Не отправляйте `history.db`, `key.pem`, pairing-коды, bearer-токены, содержимое TestFolder или скриншоты с частными запросами.

Если есть Android Platform Tools:

```powershell
adb devices
adb shell dumpsys package com.vanyabridge.app
adb logcat -c
```

После воспроизведения именно падения приложения:

```powershell
adb logcat -d -b crash -v threadtime > vanyabridge-crash-local.txt
```

Файл crash-буфера сначала просмотрите локально и удалите персональные данные/сообщения других приложений перед передачей.
Клиент намеренно не пишет токены/тела запросов в logcat. Для сетевой ошибки достаточно статуса UI, состояния ПК и точного шага; не включайте полное логирование HTTP Authorization.
