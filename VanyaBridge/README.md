# VanyaBridge 0.1 MVP

Отдельное приложение Android ↔ Windows с чатом и локальными инструментами.
Это **новый проект**, не переименованный VoiceAgent-v2: исходники и исправления VoiceAgent не изменены.
Голосовой ввод, Vosk, Telegram и старый APK VoiceAgent в этот проект не входят.

Реализован исполняемый MVP; приёмка на Windows 11 и OnePlus 13 ещё необходима.
В архиве есть собранный `releases/VanyaBridge-debug.apk`. Windows EXE здесь не собран.
Точные результаты и ограничения: [TEST_RESULTS.md](TEST_RESULTS.md).

## Быстрый запуск на Windows 11

1. Распакуйте весь проект, например в `C:\VanyaBridge`. Для Android Gradle на Windows используйте путь без кириллицы.
2. Установите Python **3.12 x64** с компонентом Tcl/Tk и Python Launcher (`py`).
3. Откройте PowerShell в папке проекта:

```powershell
.\START_WINDOWS.bat
```

Первый запуск создаёт `.venv` и устанавливает Python-зависимости. По умолчанию сервер доступен **только этому ПК**.
Если установка прервалась, выполните `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и повторите запуск.
API-ключи не нужны. Платные API не вызываются.

Для телефона узнайте IPv4 Wi-Fi адаптера командой `ipconfig` и запустите:

```powershell
.\START_WINDOWS.bat --host 192.168.1.100
```

Замените адрес на **свой LAN IP**. Адрес должен принадлежать ПК. `0.0.0.0` и публичные адреса отклоняются.
Если Windows запросит доступ через брандмауэр, разрешите его только для частной сети. Не включайте проброс порта на роутере.
По умолчанию используется TCP 8765. Для другого порта добавьте `--port 8766`.

## Подключение Android

1. Установите `releases/VanyaBridge-debug.apk`. Пакет: `com.vanyabridge.app`; он не заменяет VoiceAgent.
2. Подключите телефон и ПК к одной доверенной Wi-Fi сети. Изоляция Wi-Fi клиентов должна быть отключена.
3. На ПК откройте «Устройства»: там показаны HTTPS-адрес и полный SHA-256 сертификата.
4. В Android откройте «Связь», введите адрес и **все 64 символа SHA-256**. Сверьте их с экраном ПК и отметьте подтверждение.
5. На ПК нажмите «Создать одноразовый код». Введите код на телефоне и нажмите «Подтвердить на телефоне».
6. На ПК выберите появившееся устройство и нажмите «Разрешить сопряжение».
7. Дождитесь статуса «ПК подключён». После этого доступны чат, история и разрешения.

Код действует 120 секунд, одноразовый, максимум пять попыток на выпуск кода. Ожидающее подтверждение тоже истекает через 120 секунд.
При несовпадении сертификата соединение отклоняется, никакого переключения на незащищённый HTTP нет.
После перезапуска сервер сохраняет сертификат и сопряжения. На телефоне токен защищён Android Keystore.
Возвращение в приложение и восстановление Wi-Fi запускают переподключение; фоновой службы нет.
«Забыть на телефоне» удаляет локальные данные. Для действительного отзыва токена нажмите «Отозвать доступ» на ПК.

## Команды

Вкладка «Разрешения» на ПК включает/выключает действия для всех сопряжённых устройств.
По умолчанию включены только `list_files`, `status`, `search_images`, `read_page`.
Остальные действия сначала включите на ПК. Даже после включения **каждое выполнение требует отдельного подтверждения**.
После перезапуска разрешения действий снова выключаются; это консервативное поведение MVP.

| Команда | Реальное действие / условие |
|---|---|
| `Открой YouTube на компьютере` | Подтверждение → запрос стандартному Windows-браузеру. Возвращается REQUESTED, не доказательство видимого окна. |
| `Покажи файлы в моей тестовой папке` | До 200 обычных файлов непосредственно в TestFolder; ссылки, подкаталоги и запрещённые пути пропускаются. |
| `Открой VS Code` | Подтверждение → запуск Code.exe из стандартной пользовательской/системной установки. Произвольные аргументы запрещены. |
| `Найди изображения гор для обоев` | Реальный запрос к Wikimedia Commons API, до трёх JPG/PNG результатов. Нет результатов/сети — нет выдуманных картинок. |
| Выбрать результат → «Выбранное → обои» / «Выбрать для обоев» | Создаёт отдельную задачу `установи обои image:ID`, ожидает подтверждения, скачивает выбранное изображение и вызывает Windows API. |
| `Установи обои mountains.jpg` | Отдельное подтверждение; файл должен находиться в TestFolder. |
| `Открой файл example.txt` | Подтверждение; разрешены TXT/PDF/JPG/PNG/BMP в TestFolder. |
| `Статус компьютера` | ОС и свободное место диска. |
| `Открой сайт https://example.com` | Подтверждение; публичный HTTPS URL без пароля/логина. |
| `Прочитай страницу https://ru.wikipedia.org/wiki/Гора` | Playwright, ограниченный список сайтов, JavaScript выключен. Возвращает доступный текст как недоверенные данные. |

Результаты изображений содержат ссылки на источник. Перед использованием проверьте лицензию Wikimedia.
«Посмотреть изображение» открывает оригинал в браузере пользователя; скачивание для обоев происходит только после подтверждения задачи.
Просто фраза «установи выбранное изображение на рабочий стол» без выбора не угадывает файл: используйте кнопку результата или точное имя.

TestFolder находится в `%LOCALAPPDATA%\VanyaBridge\TestFolder`. Поместите туда тестовые TXT/JPG/PNG файлы вручную.
Системные программы, рабочие документы вне этой папки, произвольный shell и изменение разрешений из чата недоступны.

## Ultra Free и Standard

Ultra Free — **детерминированные Planner, BrowserAgent, SystemAgent**, не три нейросети.
Планировщик поддерживает перечисленные команды. Неизвестная команда получает честное сообщение о неподдерживаемом запросе.
Standard отображается в обоих интерфейсах, но LLM-провайдер ещё не подключён: запрос в этом режиме завершается объяснением, без сетевого вызова к LLM.
Кнопка ChatGPT копирует введённый запрос в буфер и открывает официальный `https://chatgpt.com/`.
Пользователь сам вставляет запрос/ответ. Нет чтения cookies, автоматического входа, импорта сессий или обхода лимитов.
Ответ, вставленный обратно в чат, обрабатывается обычной ограниченной грамматикой команд; сам по себе он не получает дополнительных прав.

Официальная интеграция подписки не подтверждена из этой среды: см. [docs/OFFICIAL_AUTH.md](docs/OFFICIAL_AUTH.md).

## Playwright по необходимости

Для чтения страниц один раз установите Chromium:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

Без этого работают локальные файлы/статус, сопряжение, вызов стандартного браузера, поиск Wikimedia и Windows-действия.
Chromium не запускается при старте приложения. Для каждого чтения используется свежий временный контекст без пользовательского профиля.
В MVP разрешены только `en.wikipedia.org`, `ru.wikipedia.org`, `commons.wikimedia.org`, `www.youtube.com`.
На динамических сайтах содержимое без JavaScript может быть неполным. Логин, CAPTCHA, покупки, заполнение форм и действия в аккаунтах не реализованы.

## Сборка Android

Требования: JDK 17, Android SDK 35, Build Tools 34.0.0 (либо установленные Gradle по конфигурации).
Откройте папку `android` в Android Studio, дождитесь синхронизации. В её терминале PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK: `android\app\build\outputs\apk\debug\app-debug.apk` (из корня полного проекта).
AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9. Vosk и STT-модель для этого чат-приложения не нужны.
Debug APK имеет отладочную подпись; при смене ключа сборщика обновление поверх прежней сборки может потребовать удаления приложения и нового сопряжения.

## Сборка Windows EXE

**Выполняется на Windows**, не в Linux:

```powershell
.\BUILD_WINDOWS.bat
```

Результат: `dist\VanyaBridge\VanyaBridge.exe`. Переносите **всю** папку `dist\VanyaBridge`, не один EXE.
PyInstaller-рецепт включён, но сборка/запуск EXE здесь не проверены. Браузер Chromium не включён в пакет; для чтения страниц установите его отдельно тем же пользователем.
Для LAN можно запустить `VanyaBridge.exe --host 192.168.1.100`.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Python 3.12; нет внешних LLM-запросов в тестах. Тесты работают в Linux/Windows, кроме явно отмеченных ограничений платформы.
Один TLS-тест поднимает настоящий локальный сервер, выполняет сопряжение и WebSocket-запросы. Это **не** проверка Android ↔ Windows на двух физических устройствах.
Инструкция приёмки всех пяти сценариев: [docs/MANUAL_TEST.md](docs/MANUAL_TEST.md).

## Структура и продолжение

- `android/` — Compose Material 3, TLS pinning, Keystore, WebSocket, lifecycle reconnect.
- `desktop/` — Tkinter UI, без Electron; все операции сервера идут через очередь в выделенный asyncio thread.
- `backend/agents/` — планировщик с ограниченной грамматикой и два инструментальных агента.
- `backend/engine.py` — состояния, очередь, тайм-ауты, согласования, отмена, идемпотентность request_id.
- `backend/api.py` — REST-команды и WebSocket-снимки; никакого shell API.
- `backend/security/` — локальная TLS-идентичность, одноразовое сопряжение, проверка путей.
- `backend/store.py` — SQLite история, хеши токенов, безопасный журнал событий.
- `tests/`, `validation/`, `docs/` — тесты, свидетельства проверок и ограничения.

Следующий этап: физическая приёмка Windows/OnePlus → исправление обнаруженных несовместимостей → устойчивый установщик/подпись → ревью безопасности и обновление зависимостей → официальный LLM-адаптер только после проверки условий и отдельного согласования расходов.
Интерфейс `Planner.plan → Plan` и `agent.execute → dict` позволяет подключить другой планировщик/инструменты; новый LLM не должен обходить существующие разрешения и подтверждения.
OpenAI/Gemini/Claude/локальные модели/MCP сейчас **не подключены**.
